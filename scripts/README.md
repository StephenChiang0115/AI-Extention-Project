# scripts：評估與壓測工具

這個資料夾放「不屬於後端或擴充功能本身」的測量工具，用來收集期中報告要用的數據。
所有指令都在**專案根目錄**執行，使用後端的虛擬環境（`backend\.venv`，第一次執行 `start-backend.bat` 時會自動建立）。

## 地標辨識評估（eval_landmarks.py）

階段 6 用：把一整個資料夾的真實地標照片逐張送到後端 `/api/identify`，統計**辨識準確率、信心值、延遲**，並輸出逐張結果的 CSV。

### 準備

1. 把照片放進一個資料夾（例如 `scripts\eval_samples\`），檔名規則見 [eval_samples/README.md](eval_samples/README.md)。
   簡單說：`台北101__01.jpg` 代表正確答案是「台北101」。
2. 在 LM Studio 載入支援圖片的模型並 Start Server（port 1234）。
3. `backend\.env` 設定：
   ```
   PROVIDER=lmstudio
   DAILY_FREE_LIMIT=500
   ```
   `DAILY_FREE_LIMIT` 預設只有 5，評估幾十張圖一定會被擋（HTTP 429），請先調高。
4. 執行 `start-backend.bat` 啟動後端（http://localhost:8080）。

### 執行

```bat
backend\.venv\Scripts\python scripts\eval_landmarks.py scripts\eval_samples
```

常用選項：

| 選項 | 說明 |
|---|---|
| `--api URL` | 後端網址，預設 `http://localhost:8080` |
| `--out 檔名.csv` | 逐張結果輸出位置，預設 `results.csv`（目前資料夾） |
| `--client-id ID` | 指定 `X-Client-Id`。預設每次執行產生新的隨機值，避免上一次的額度影響這一次 |
| `--page-title-from-filename` | 把正確答案當成網頁標題（`page_title`）送出，模擬「網頁標題含地名」的情境（例如 Google 地圖）。**這會把答案告訴模型**，只適合用來比較「有脈絡 vs 只看圖」的差異 |
| `--twice` | 每張圖送兩輪，第二輪統計快取命中率 |
| `--max-side 1280` | 影像最長邊上限（像素）。手機照片常是 4000px 以上，縮小後送出較快，也確保低於後端 2 MB 上限 |
| `--timeout 180` | 單次請求逾時秒數。本機模型第一次載入或圖片很大時可能很慢 |

### 輸出

終端機會逐張顯示 `✔`／`✘`、預測名稱、信心值與延遲，最後印出摘要：

```
=== 摘要 ===
  圖片張數                        7
  成功回應                        6
  正確（寬鬆比對）                2
  準確率（正確／成功回應）        33.3%
  準確率（正確／圖片張數）        28.6%
  無法辨識（landmark_name 為空）  0
  平均信心值                      0.930
  快取命中                        0／6（0.0%）
  延遲 p50                        16 ms
  延遲 p95                        75 ms
  延遲 平均                       28 ms
  錯誤數（非 200）                1
  其中 429（額度用完）            0
```

（上面是 mock 模式的範例：mock 永遠回答「台北 101」，所以只有檔名是台北101 的圖算對。）

CSV 欄位（UTF-8 含 BOM，Excel 直接開啟不會亂碼）：

| 欄位 | 說明 |
|---|---|
| `file` | 檔名 |
| `expected` | 從檔名取出的正確答案 |
| `pass_no` | 第幾輪（`--twice` 時有 1、2） |
| `landmark_name` | 模型回答的地標名稱（空白代表無法辨識） |
| `confidence` | 模型信心值（0～1） |
| `correct` | 是否答對（寬鬆比對，見下） |
| `cache_hit` | 後端是否命中快取 |
| `latency_ms` | 從送出到收到回應的時間（客戶端量測，含網路與模型推論） |
| `status` | HTTP 狀態碼；`0` 代表沒送出（讀圖失敗或連線失敗） |
| `error` | 錯誤訊息 |
| `image_bytes` | 實際送出的影像大小（縮圖／轉檔後） |

### 判斷「答對」的方式

寬鬆比對：兩邊都先去掉空白與標點、全形轉半形、不分大小寫，然後只要「正確答案包含在預測裡」或「預測包含在正確答案裡」就算對。
例如正確答案「台北101」、模型回答「台北 101 大樓」→ 算對。

限制：

- 不懂同義詞與中英文對照。「台北101」對「Taipei 101」不算對，「臺北」對「台北」也不算對。
  需要時在檔名用 `=` 列出多個可接受名稱：`台北101=臺北101=Taipei 101__01.jpg`。
- 包含關係可能誤判，例如正確答案「台北」會讓任何含「台北」的回答都算對。正確答案請寫完整地標名稱。
- 報告用的最終數字建議再人工檢查一次 CSV 的 `landmark_name` 欄。

### 注意事項

- **額度**：只有未命中快取的請求會扣額度，辨識失敗（502）會退還。額度存在記憶體，重啟後端就歸零。遇到 429 時，工具會提示調高 `DAILY_FREE_LIMIT`。
- **快取**：同一次執行裡，若兩張照片的 dHash 很接近，第二張可能直接命中第一張的快取結果（`cache_hit` 為 True），這時延遲與答案都不是模型產生的。統計模型表現時可只看 `cache_hit=False` 的列。信心值 < 0.6、無法辨識或低紋理（縮到 32×32 後幾乎沒有亮度變化）的圖不會寫入快取，所以 `--twice` 第二輪也不會命中。
- **重新跑**：每次執行預設用新的 Client-Id，但快取是全後端共用的；想讓模型重新辨識同一批照片，請重啟後端清空快取。
- **延遲**：本機模型第一次請求通常特別慢（載入模型），可以先送一張暖機，或看 p50 而不是平均值。

## 壓測（loadtest.py）

模擬多位使用者同時框選，量測快取命中率、延遲 p50/p95/p99、吞吐量、額度行為與快取省下的模型費用。完整選項見 `loadtest.py` 開頭說明。

```
backend\.venv\Scripts\python scripts\loadtest.py --api http://localhost:8080 --requests 200 --concurrency 10 --clients 20 --distinct-images 15 --out report.json
```

- 影像是合成的有紋理圖，同一張圖的變化只改壓縮品質與 ±5% 縮放，所以命中率是**最佳情況**；真實使用者裁切範圍不同時常常不會命中。
- 客戶端延遲包含排隊與上傳時間，`/api/stats` 的延遲只算伺服器內部處理，兩者差很多；報告要註明引用哪一個。
- 要取得乾淨的伺服器端數據，請用專用 port 並重新啟動後端（快取與額度在記憶體裡）。
- mock 模式沒有模型延遲，命中與未命中的延遲差距要接 LM Studio 或雲端模型才看得出來。
