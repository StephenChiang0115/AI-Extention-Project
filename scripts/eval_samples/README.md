# eval_samples：評估用地標照片

把要拿來評估辨識品質的照片放在這個資料夾，再執行：

```bat
backend\.venv\Scripts\python scripts\eval_landmarks.py scripts\eval_samples
```

（工具只讀這一層的圖片，不會進子資料夾；這份 README 會自動略過。）

## 檔名規則

```
<正確地標名稱>__<編號>.<副檔名>
```

- 名稱與編號之間是**兩個底線** `__`。
- 支援 `.jpg`、`.jpeg`、`.png`、`.webp`。
- 沒有 `__` 時，整個主檔名就是正確答案（例如 `圓山大飯店.jpg`）。
- 有多個可接受的名稱時用 `=` 分隔（任一個對上就算對）。

範例：

| 檔名 | 正確答案 |
|---|---|
| `台北101__01.jpg` | 台北101 |
| `台北101__02.png` | 台北101 |
| `圓山大飯店__01.jpg` | 圓山大飯店 |
| `中正紀念堂=中正紀念堂自由廣場__01.webp` | 中正紀念堂 或 中正紀念堂自由廣場 |
| `艾菲爾鐵塔=Eiffel Tower__01.jpg` | 艾菲爾鐵塔 或 Eiffel Tower |

## 建議

- 名稱用模型通常會回答的寫法（後端提示詞要求繁體中文），例如「台北101」而不是「Taipei 101」；不確定就用 `=` 多列幾個。
- 每個地標放 2～5 張不同角度、距離、天氣的照片，比「很多地標各一張」更能看出穩定度。
- 可以放幾張「不是地標」的照片（例如 `無__01.jpg`）觀察模型會不會亂猜；這類圖算不算對要人工看 CSV 判斷。
- 照片模擬真實使用情境：使用者是在網頁上框選，所以截圖、影片畫面、地圖街景都比專業攝影照更具代表性。
- 大圖會自動縮到最長邊 1280px 再送出（`--max-side` 可調），不用自己先縮。
- 照片可能有著作權，請不要把它們提交到版本控制。
